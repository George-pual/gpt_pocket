# MATH L2–3任务的数据划分与SFT能力保持方案

本文件回答：评测MATH L2–3时从哪里选SFT/GRPO数据，以及怎样尽量减少SFT造成的数学能力损失。以下为建议实验，不预设训练结果；“保住正确率”是需要验证的目标。

2026-10-13数据范围修订：最初505条来源由用户确认为unsloth/OpenMathReasoning-mini；后续以MATH train/test L2–3为主，GSM8K改为可选对照。当前数量与阶段关系见[MATH主线配置](MATH_L2_L3_DATA_CONFIGURATION.md)，不是对历史训练量的改写。

## 1. 同难度选训练数据，但测试题保留作评测

**可以优先从MATH训练集的Level 2–3选题；不要从测试集抽题补训练。**这是匹配任务分布，不是匹配测试答案。

| 用途 | 建议来源 | 进入流程的形式 |
|---|---|---|
| 新SFT示范 | MATH train L2–3；原505条外部示范保留为历史来源 | 问题＋经核验的完整解答 |
| GRPO主实验候选 | 与SFT题簇分离的MATH train L2–3 | 问题＋奖励侧gold，回答在线生成 |
| 开发验证 | 从原始train预留，先按题簇固定划分 | 用于选checkpoint与参数，不再训练 |
| 最终确认 | 未参与训练、选数或调参的数据 | 固定方案后评估，说明来源及污染检查范围 |
| 现有MATH L2–3 test | 历史评测与错误复盘 | 已反馈到设计中，不能重新称全新盲测 |

同一个数据集、同一个level里可以有不同训练/测试实例。原始level只是难度参照，同为L2不代表当前模型成功率相同。SFT与GRPO可以共享知识点；初版将题目实例分开，便于分析泛化和归因，并非算法硬性要求。

外部开源扩展数据也可以使用，但要追溯原题，排除MATH测试原题、翻译与明显派生题。下载了“另一个数据集”不自动获得独立性。

### 1.1 本地可用规模，不把题池重复计算

本次读取`datasets/math/raw/*/train-*.parquet`的level字段，得到：

| MATH学科 | train L2 | train L3 |
|---|---:|---:|
| Algebra | 340 | 392 |
| Counting & Probability | 119 | 160 |
| Geometry | 100 | 129 |
| Intermediate Algebra | 167 | 301 |
| Number Theory | 131 | 191 |
| Prealgebra | 329 | 251 |
| Precalculus | 162 | 168 |
| 合计 | 1348 | 1592 |

合计2940条原始行；历史候选构建中规范化去重后MATH为2939题。最终可用量还受同题聚类、SFT/验证排除、缺图、gold和轨迹质量影响。

因此不能宣称“用全部L2–3做SFT，再用另外几千道不同的L2–3做GRPO”。要从同一有限题池先划分；原505题若有重叠也需排除。新一轮从Base重训与从旧adapter续训要分别记录，后者还要考虑历史已用题的暴露。

### 1.2 针对当前任务的起始配比

本轮优先预留**600道MATH SFT候选题**，不默认把它全量追加到505题上：

- MATH train L2–3目标600题：L2约270、L3约330。
- GSM8K不设强制配额；出现明确算术、单位或文字建模短板时再单独对照。
- MATH内部覆盖上表七个学科；条件建模、边界、计算回代与收尾作为额外行为标签。
- 先预留开发验证及确认数据，再从其余题簇分SFT与GRPO；不足合格样本则缩小数量。

L2/L3约45%/55%接近当前训练来源分布，不是最优比例。600只是候选数；经Base每题4答及质量核验后，每题最多选一份，最终训练数N≤600，以清单为准。最初505条与新MATH题的整体差异不能全部归因于解答来源；比较官方示范与Base自身轨迹时，优先固定同一批题目。

GRPO具体执行统一见[当前GRPO数据方案](GRPO_DATA_PLAN.md)：预留200道MATH开发题和600道SFT候选后，至多2139道MATH题进入后续排除与筛选。先抽最多512题校验流程，用最终选定起点每题4答，completion预算3894；合格池首轮最多1024题，保持合格池学科、Level与k分布，不强制25/50/25难度配额。MATH不足时缩小规模。首轮256 updates只计划消费约512个问题位置，不把合格池大小当已训练量。以上均待执行。

## 2. “补更多正确数据”为什么仍不够

标准SFT对每个参考token做预测。即使最终答案正确，它也会推动模型模仿参考解答的措辞、路径与停止方式。如果参考过程有错、缺关键步骤、风格与模型差距较大，或训练更新不合适，数学表现仍可能下降。

当前v3已经检查prompt/padding mask、真实EOS与训练长度；最长1777不超过2048。它只训练了32个updates。已有事实不足以认定“训练太久”“2e-5一定太大”或“所有退化都是脏数据”。

尤其要区分：`completion_only_loss=True`意味着监督整个回答，包括数学正文，**不等于只训练格式标签**。

接下来优先检验“示范是否适合这个Base”与“更新多大合适”，而非直接重复追加外部解答。

## 3. 公开方法中值得借鉴什么

| 来源 | 核对到的做法/观察 | 对本项目的启发与边界 |
|---|---|---|
| [RFT：Scaling Relationship…](https://arxiv.org/abs/2308.01825) | 生成并收集正确推理路径用于再训练 | 借鉴验证后保留自身轨迹；原文采用监督模型生成，不将下面的Base变体称为原配方 |
| [GRAPE](https://arxiv.org/html/2502.04194v2#S3) | 对固定问题的多个候选解答，按目标模型条件概率选更适配的回答 | 质量门槛之后再看与Base的接近程度；不是在全题池只选最容易的问题 |
| [DFT论文](https://arxiv.org/html/2508.05629v1#S3.SS3) | 用停止梯度的目标token概率加权NLL | 可以作为单独loss对照；不保证保留全部能力，低概率格式token也可能学慢 |
| [推理SFT优化条件研究](https://arxiv.org/abs/2604.06628)及[作者代码](https://github.com/Nebularaid2000/rethink_sft_generalization) | 泛化与数据、优化过程及模型能力有关，部分设置先下降再恢复 | 更低LR/更早停止不普遍更好；不同规模、长CoT和硬件配方不能直接照搬 |

这些研究提供假设与实验依据，不提供本项目必然不掉点的保证，也不能据此断言已找出v3根因。

## 4. 首选路线：保留Base会做的解法，减少示范分布变化

### 4.1 先试不用参数更新的输出约定

保留当前Base对照，再单列一个更清晰的格式提示方案。统一题目、解码与评分，比较数学正确率和原生格式。若仅需系统可读取最终答案，也可评估确定性提取/包装，但分别报告模型原生输出与后处理输出。

提示与后处理会影响生成或评价，仍需验证；它们的好处是避免为格式目标直接修改模型参数。新提示不能只给某个模型使用后与旧提示Base比较。

### 4.2 用训练题生成SFT候选解答

冻结Qwen3-4B-Base，对已分配的SFT训练题生成少量候选，初版每题最多4条。先核验最终答案、推导关键步骤、完整性和正常结束，再从合格轨迹选择一条。

选择次序：

1. 问题/gold可靠；解答正确且具有必要依据。
2. 不重复、未截断、无跑题或“假验证”。
3. 在上述门槛内，优先保留Base自然生成的完整解法。
4. Base本轮没有合格轨迹时，使用复核过的官方/外部解答或暂缓；保留失败原因，检查是否丢失整个学科/技能。

它是带验证的自身轨迹筛选，受RFT与模型适配数据选择启发。**最终答案判对仍不认证全过程，Base自己的回答也会有错。**不能把仅因答案碰巧正确的过程变成保真锚点。

同题有多条候选时，可将Base条件概率作为辅助排序。记录序列log probability与平均每token NLL，检查长度偏差；任何长度归一化改动都是本项目变体，不冒充GRAPE原始实现。新模板中强制添加的标记也会影响打分，应固定评分模板并区分数学正文与格式部分。

### 4.3 格式转换只改必要边界

尽量保留已核验的数学正文，只统一推导/最终答案边界及真实EOS；不一边转换格式一边大幅压缩、换解法或加入长反思。保存转换前后内容、最终答案提取依据与tokenizer检查。

“只改格式”描述的是数据转换，不表示训练梯度只作用于格式。若用完整completion NLL，正文仍被监督。

这套选数可能偏向Base已会的题，适合能力保持/格式冷启动，却可能较少教会新能力。必须保留知识点分层与失败题审查，不能把自身采样正确率当唯一数据质量标准。

## 5. 第二道措施：控制更新并尽早看到真实生成效果

优先从同一Base重新初始化LoRA做恢复实验，便于与v3比较；继续训练旧adapter可以另设对照，不能把换起点后的差异全部归因于数据。

| 设置 | 起始建议 | 说明 |
|---|---|---|
| 训练目标 | 先完整completion NLL | 使用上述Base适配且复核过的示范 |
| LR | 5e-6与1e-5两档 | 都从同一起点；2e-5保留为历史参考，严格对照需同条件重跑 |
| 更新预算 | 首轮最多64 updates | 是有上限的探索，不承诺64足够或必须跑满 |
| 保存与生成验证 | 0、8、16、32、64步 | 单次运行调度终点固定为64，避免每个checkpoint重设scheduler |
| warmup/scheduler | 4步warmup、linear | 两臂一致，本项目建议值 |
| 有效batch | 16，microbatch4×累积4 | 显存不足可改变拆分，先保持有效batch |
| LoRA | r32、alpha64、dropout0 | 首轮不同时改变rank或target_modules |
| 序列 | 总长2048，无机械截断 | 过长示范换完整可用解法或暂排除 |

低LR减小一步的更新幅度，但不自动保证最终输出更好。验证暂时下降时先检查是否多题同类退步、截断/格式失控；保留checkpoint，由人决定是否在预定预算内继续观察。研究中的先降后升不能成为无限追加训练的依据。

验证至少报告：MATH/GSM8K各自正确率、Base对→SFT错与反向翻转、格式且EOS、截断、重复、长度，以及累计监督tokens、实际题目覆盖与重复次数。

## 6. 若仍掉点，按成本选择后续保护措施

| 方法 | 适用情况 | 代价与限制 |
|---|---|---|
| DFT替代NLL | 相同合格示范下，怀疑低概率目标的拟合方式不合适 | 单独比较loss；不能将更小loss/梯度当成功 |
| 降低数学正文监督权重 | 格式是主要目标，完整正文模仿仍带来能力损失 | 需自定义token权重与归一化，格式/EOS可能被过度强调 |
| 仅监督边界标签与EOS | 作为小规模诊断，区分正文模仿与格式适配 | 梯度通过共享权重传播，仍可能影响数学、引发过早结束；不是能力不变的保证 |
| Base分布KL正则 | 明确需要约束数学正文的分布偏移 | 增加参考前向和内存/算力；应区分希望改变的格式与希望保留的正文 |
| 经验证的Base轨迹回放 | 新示范学习与旧能力保持需要权衡 | 回放本身也会有选择偏差；不能未经复核重放原505错误示范 |
| Base直接GRPO | SFT候选持续数学退化，且Base已能产生可判分成功轨迹 | 重新按Base校准题池，与SFT后GRPO公平比较 |

首轮优先“适配数据＋普通NLL＋两档LR”；仍有问题时先考虑DFT这一低侵入对照。token加权、仅格式监督和KL不同时叠加，以免无法归因。

### 6.1 已核对的软件支持与尚缺实现

官方TRL v0.23.1的[SFTConfig](https://github.com/huggingface/trl/blob/v0.23.1/trl/trainer/sft_config.py)和[SFTTrainer](https://github.com/huggingface/trl/blob/v0.23.1/trl/trainer/sft_trainer.py)包含`loss_type="dft"`。token级公式为：

```text
NLL: L = mean(-log p_theta(y_t | prefix))
DFT: L = mean(-stop_gradient(p_theta(y_t | prefix)) * log p_theta(y_t | prefix))
```

实际使用需沿用正确shift、有效token归一化、prompt/padding mask和真实EOS。DFT是可测试的目标，不是零遗忘约束。

本地`vllm_speed_tools/train_reviewed_sft.py`目前硬编码lr2e-5、1epoch等配置，没有本文所有实验开关；本地CPU环境未安装TRL。此次只核对上游固定版本源码与历史入口，未修改训练脚本、安装训练依赖、验证GPU兼容性或启动训练。不能复制上面概念公式就宣称已实现训练。

## 7. 最小消融，怎样判断确实“保住”

| 阶段 | 对照 | 固定项 | 要回答的问题 |
|---|---|---|---|
| P0 | 当前Base提示 vs 新格式提示 | 题集、解码、评分；单列提示差异 | 是否确实需要SFT才能满足输出需求 |
| P1 | 同题复核官方解答 vs Base适配合格解答 | 相同问题、NLL、LR5e-6、64步调度、LoRA | 减小示范差异是否有价值 |
| P2 | 5e-6 vs 1e-5 | P1选定数据、调度与其余配置 | 更新幅度与格式学习怎样权衡 |
| P3，按需 | NLL vs DFT | 同一数据、起点、先用同一LR及预算 | loss选择是否改善能力保持 |

P1在双方都有合格轨迹的共同题集进行，不能一臂全是容易题、另一臂全是难题；其余题另作整套选数策略比较。解答长度差异、监督tokens与轨迹生成成本均报告。P3同LR比较是固定预算目标函数比较，不证明每个目标各自调优后的上限。

先用预留200道MATH题开发验证粗筛，1题对应0.5个百分点，这个规模不足以可靠证明“最多掉1个百分点”。开发集也不得按Base是否答对来选择，只在报告中额外分析Base已判对的子集。

可以预先设“格式且EOS≥90%，数学判对率允许损失不超过1个百分点”为候选目标，但这只是项目门槛示例。候选均不满足时不选SFT；观察分数接近不等于已证明非劣。

最终声明需要：锁定候选→独立训练seed→未参与选数/调参的确认数据→逐任务配对差值与区间。若差值区间下界仍低于预设非劣界限，应称证据不足，不能把“差异不显著”说成完全无损。

本项目现有官方测试已用于反馈，下一轮确认来源及可用数量要在划分时确定。数据规模和训练随机性不足时，保留“不确定”，不承诺绝对正确率不下降。

## 8. 建议采用的项目讲法

> 我们评测MATH L2–3，所以训练数据优先来自MATH训练集同等级，并保留GSM8K作为基础覆盖；开发验证、SFT与GRPO先按题簇分开，测试题只用于评测和复盘。
>
> SFT v3退化后，我没有默认继续追加外部解答就能解决。我计划先保留Base在训练题上已经能生成的正确完整解法，尽量只统一输出边界，再用较小学习率与多个早期checkpoint验证格式适配是否损害数学能力。这样的目的，是减小示范与Base行为的差异。
>
> 如果仍有退化，再单独比较DFT等训练目标；如果SFT候选始终不合格，就保留Base直接GRPO。最终是否保住正确率要靠独立验证和配对比较，而不是依据方法看起来合理。

与[项目推进主线](PROJECT_DEVELOPMENT_STORY.md)和[通用数据方案](DATA_DESIGN_PROPOSAL.md)配套。当前目标下，本文件的保守路线优先于“复核505条后直接追加800条并扩大训练”的旧起始建议。
