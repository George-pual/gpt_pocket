# SFT与GRPO训练问题排查复盘

整理日期：2026-10-12。

这份文档回答四件事：训练中出现什么问题、分析依据是什么、做过什么处理、处理后有什么变化。使用第一人称方便项目讲述；涉及本人贡献时应按实际参与程度调整。它是根据现有记录做的回顾性复盘，不把事后分析说成启动前已知，也不虚构精确的排查时间顺序。

实验配置与运行清单已单独保留在[实验索引](TRAINING_EXPERIMENT_INDEX.md)。以下重点是问题排查，不再按运行编号罗列参数。

## 一、SFT结果不满意：格式更规整，但数学能力反而下降

### 我遇到了什么问题

SFT训练能完成，loss也没有直接暴露异常，但生成评测并不满意。统一v3.2评分下，MATH2024题的结果是：

| 指标 | Base | SFT v3 |
|---|---:|---:|
| 自动判对率 | 74.70% | 65.71% |
| 格式且EOS | 63.49% | 91.55% |
| 截断率 | 1.93% | 5.63% |

模型更经常遵循标签，却没有同时保持答案正确性，收尾也有退化。因此，“SFT学会格式”与“SFT达到项目目标”需要分开判断。

### 我怎么分析

复盘时，我把问题拆成实现、监督内容和更新幅度三层，避免看到掉点就直接增加epoch。

**先看监督是否实现正确。** 已有训练入口会检查prompt和padding是否屏蔽、completion与真实EOS是否进入labels。训练上限2048，实际最长1777，没有训练截断。因此，当前证据不支持优先归因于“EOS被截掉”或“误监督prompt”。这些是已检查的项目，不补写成当时实际发生过的bug。

**再看loss与任务目标是否一致。** 57条验证样本的loss从0.2172062到0.2123663，只说明对这些参考解答的拟合略有变化，不能说明模型在独立题目上的自由生成更准确。

**然后检查数据与更新幅度。** 后续复核发现部分解答有算术、条件、证明完整性等问题，说明监督质量值得排查；505条数据也可能覆盖不足。但当前本地数据经过修改，不能把它直接当作当时adapter的输入快照。学习率2e-5同样只是一个起始设置，没有经过这批数据的充分对照。

我的优先怀疑是监督内容/覆盖与更新幅度的组合，而不是直接断言“数据少导致过拟合”或“学习率一定太大”。

### 我做过哪些处理

- 在训练入口检查completion-only监督、真实EOS与padding边界，排除一部分常见实现错误。
- 保留Base对照，分别看正确率、格式、EOS、截断、重复与长度，不只看loss。
- 对部分训练解答做后续复核和独立版本修订，保留来源与哈希；修改数据没有追溯改变旧adapter。
- 主实验继续以SFT v3作为起点进行GRPO，用可验证结果奖励检验是否能恢复正确率和收尾。

### 处理后的效果

GRPO-1536相对SFT v3：MATH自动判对率65.71%→72.58%，截断率5.63%→2.57%，格式且EOS为91.55%→96.49%。这支持后续GRPO恢复了部分能力损失，并改善输出行为。

但MATH仍低于Base的74.70%。这个结果没有证明SFT数据问题已经修好，也不能把GRPO收益归因于后来的数据清洗。

### 哪些还没有解决

SFT退化的因果来源尚未分离。下一步应从同一Base做“原始快照/同题复核版 × 2e-5/5e-6”的四组对照，固定其余条件，再判断数据和更新幅度的贡献。此消融尚未执行。

**面试表述：**“我发现SFT主要改善了格式，却损害正确率，所以没有用loss下降宣布成功。复盘先核对监督mask和EOS，再检查解答质量与更新幅度。GRPO恢复了部分正确率，但SFT根因还需要控制变量验证。”

证据：[SFT与主训练交付报告](../deliverables/SFTv3_GRPO_1536_training_handoff/TRAINING_REPORT.md)、[SFT监督检查代码](../vllm_speed_tools/train_reviewed_sft.py)、[数据修订边界](../sft_quality_audit_v2/revision_20261011_user15/README.md)、[统一评测](../datasets/math/test_l2_l3_remaining_v1/combined_analysis_v32_final/ANALYSIS.md)。

## 二、SFT回答反复推导：更短不等于更正确

### 我遇到了什么问题

早期E1支线里，一些回答已经得到答案，还重复展开另一套推导；也有回答长到上限仍未结束。仅降低输出上限可能直接截断尚未完成的推导，因此不能作为“减少无效推理”的充分方案。

### 我怎么分析

我查看相同题目的原始回答，区分三种情况：得出正确答案后重复推导、尚未解出而持续探索、数学错误后的循环。只有第一类能明确作为“可以收束”的示例，不能把所有长回答都视为无用。

### 我做过哪些处理

早期支线做过补充SFT，并在相同8题、相同greedy解码及3894-token预算下比较原E1与补充SFT输出。

### 处理后的效果

8题中平均长度2745.8→1596.4 tokens，正常结束5/8→6/8，截断3/8→2/8，正确数仍为2/8。

一个相同答对的例子中，原模型得到53后又用另一种方法重做，补充SFT输出用一次推导结束，长度1663→546 tokens。这是行为改善的具体例子，但8题不足以证明普遍保持正确率。

另一版SFT v4在2024题上也更短，但判对率68.48%仍低于Base。这使我不能把“更短”直接认定为整体成功。

### 哪些还没有解决

这段E1支线、SFT v3和SFT v4并非同一模型的连续checkpoint。它们共同提示需要同时验证长度与能力，但不能拼成“每轮都持续改善”的时间线。

**面试表述：**“我用逐题回答区分重复推导和必要探索，再用小规模配对评测检查收束行为。确实看到更短的例子，但大评测并未支持能力保持，因此保留了负结果。”

证据：[E1与补充SFT配对诊断](../sft_closure_results/REPORT.md)、[v4分析](../datasets/math/sft_v4_vs_base_v32/ANALYSIS.md)。

## 三、GRPO新增奖励没有效果：奖励执行了，但没有独立学习方向

### 我遇到了什么问题

早期B/C各训练10步：B使用正确性和软长度惩罚，C额外给正确、格式完整且有EOS的回答0.1奖励。固定8题上两组都是3/8正确，没有净收益。

### 我怎么分析

复盘没有只比较reward均值，而是检查每项奖励在实际rollout里是否触发，以及是否改变同题回答之间的相对优势。

发现两个直接问题：

1. 长度惩罚从3382 tokens开始，B/C所有训练回答都更短，所以实际惩罚一直为0。
2. C的14条正确回答全部格式完整且有EOS，其余回答不得结束奖励，因此实际总奖励就是1.1×正确性。

GRPO的组内优势为：

```text
A_i = (r_i - mean(r)) / (std(r) + epsilon)
```

如果奖励统一乘1.1，分子与标准差同步缩放，除epsilon外基本抵消。加了奖励项，不等于增加新的优化方向。

### 我做过哪些处理

- 用B/C对照保留相同初始化、题序和主要配置，检查奖励实现分支。
- 对实际采样的奖励触发和组内差异做审计，区分“实现没执行”和“执行了但没有可识别作用”。
- 将本轮结果判定为不足以证明长度惩罚或结束奖励有效，不把在线正确数9/40与14/40当作独立测试提升。

### 处理后的效果

解决的是实验解释问题：明确本轮没有真正检验长度惩罚，也不能识别结束奖励独立收益。没有已验证的模型能力提升。

### 哪些还没有解决

尚未完成可以区分这些奖励作用的新训练对照。后续先统计“正确但长”“正确但格式坏”“错误但格式好”等样本覆盖，再设计奖励；不能为了触发惩罚而任意降低长度阈值。

**面试表述：**“我最初把奖励项加进去了，但复盘发现它在实际数据里没有新增信号。长度惩罚没有触发，结束奖励又近似是正确性奖励的等比例缩放。因此先检查有效性，再决定是否重训。”

证据：[B/C奖励对照与可识别性分析](../closure_BC_results/REPORT.md)。

## 四、GRPO正确回答拿到错误奖励：评分器污染了相对优势

### 我遇到了什么问题

模型最终答案可能包含文字、单位或等价表达，旧评分规则会漏判。对主训练6032条MATH回答的事后审计，识别出12条正确性从0修为1，涉及11个有效题组。

### 我怎么分析

我把评分链路拆为最终答案提取、表达式解析和等价比较，再检查误判如何影响同组其他回答的基线，而不是只给评测总分补几题。

一个例子的奖励是：

```text
旧：[1.1, 0.1, 0.1, 1.1]
新：[1.1, 0.1, 1.1, 1.1]
第三条减组均值：-0.5 → +0.25
```

这说明漏判可以使正确回答得到负的中心化信号。它不是模型最终概率必然下降的证明，因为还有KL及其他token的更新。

### 我做过哪些处理

- 修订部分最终答案提取与验证规则，补充正反例。
- 使用修复后的v2评分器离线重评，保留原始reward，并单独保存修复字段。
- 重建受影响题组的advantage，量化影响，而不是覆盖历史训练结果。

### 处理后的效果

修正已识别12条奖励判断，影响11组、44条回答的advantage。解决的是这部分奖励漏判及其可追溯性，没有重训，因此没有模型提升数字。

### 哪些还没有解决

12条不是全部潜在漏判上限，也不能解释整体能力差距。若验证修复能否改善训练，需要同起点、同题序、同预算比较旧/新评分器；当前尚未完成这项因果训练对照。

**面试表述：**“评分器也是训练系统的一部分。我不仅修复漏判，还复算同组优势，看它是否改变了学习方向。但离线奖励变正确，不等于旧模型能力自动提高。”

证据：[奖励信号审计](../datasets/grpo_candidates_gsm8k_math_l2_l3/training_audit_1536/reward_signal_audit_v2/ANALYSIS.md)。

## 五、GRPO后期不持续涨点：学习率假设没有通过一致性验证

### 我遇到了什么问题

主实验从1024到1536步，checkpoint评测不单调。训练后段LR逼近零，但仍有混合题组和非零梯度，因而怀疑调度可能限制预算利用。

### 我怎么分析

我把“日志LR很低”当作候选解释，而不是根因结论：梯度非零可能含KL贡献，grad_norm也不等于实际Adam参数更新量。增加训练步数未必提高独立测试正确率。

### 我做过哪些处理

已有A/B实验从同一GRPO-1024 checkpoint开始，各训练256步，使用同一题池、题序、修复v2奖励和重建的optimizer。

- A：2e-6线性衰减至0，保留2步warmup。
- B：全程恒定2e-6，无warmup。

比较相同评测题、prompt和解码条件下的逐题结果，而非只比较训练reward。

### 处理后的效果

| 历史评分口径 | A线性 | B恒定 |
|---|---:|---:|
| GSM8K /1319 | 1119 | 1110 |
| MATH /200 | 138 | 141 |

B相对A在MATH多3题、GSM8K少9题，没有一致收益，配对不确定性未排除波动。现有分析不支持把恒定LR设为新默认，也削弱了“衰减是唯一主因”的解释。

### 哪些还没有解决

两组warmup也不同，比较的是完整调度策略，不是严格只改衰减；只有一个训练seed。后续应先检查已有中期checkpoint，再视需要统一warmup、补独立seed。A有KL/梯度尖峰，也应单独定位，不用它解释全部差异。

这里使用历史评分口径，不能直接和当前v3.2主结果表混算。

**面试表述：**“我根据后期学习率提出假设，并做了调度对照。但结果没有支持两个测试集一致改善，所以没有坚持最初解释，而是继续排查数据和有效奖励信号。”

证据：[学习率对照分析](../lr_ab256_experiment/ANALYSIS.md)。

## 六、GRPO有些题组不提供正确性差异：筛选与在线采样不能混为一谈

### 我遇到了什么问题

同一道题的4条回答如果总奖励都相同，组内策略advantage为零。早期C64有63/132组总奖励相同；主1536步实验按正确数统计，0/4与4/4合计约25.2%。这两个阶段不能混用同一个比例。

### 我怎么分析

“正确数相同”和“总奖励相同”需要分开：格式或长度有差异时仍可能有策略信号；即使总奖励相同，未被mask的回答仍可能产生KL梯度。

还要区分筛选时回答和训练时回答。旧策略筛选出的混合题组，在线重新采样后也可能全对或全错。

### 我做过哪些处理

主实验使用SFT v3对候选每题生成4条，优先选择1–3/4正确的混合题组，再排除已知重叠和截断等情况。训练后按题组审计正确数、奖励与屏蔽情况，区分准备池和实际消耗题目。

### 处理后的效果

完成3072个不同训练题组的覆盖及有效性核查，明确静态筛选未能消除在线的同奖励组。不能声称已实现在线动态过滤，也不能把有混合组直接等同于泛化提高。

### 哪些还没有解决

在线补采样/动态过滤尚未在主实验实施。若以后做，需要完整保留四回答题组、设置重采样上限，并比较生成token和wall time。只对齐optimizer steps会忽略额外采样成本。

**面试表述：**“我使用混合题组筛选增加相对奖励信号，但也核对了在线分布。静态筛选不保证在线每组有效，动态采样是下一步方案，还没有写成已完成改进。”

证据：[主训练交付](../deliverables/SFTv3_GRPO_1536_training_handoff/TRAINING_REPORT.md)、[各正确数组审计](../datasets/grpo_candidates_gsm8k_math_l2_l3/training_audit_1536/correctness_groups_five_bins/ANALYSIS.md)、[C64诊断](../vllm_C64_results/REPORT.md)。

## 七、GRPO单卡工程问题：先能稳定运行，再谈吞吐和效果

### 我遇到了什么问题

早期B/C的长序列反向预检，microbatch=4发生OOM。迁移到vLLM后还要处理NF4训练与BF16生成的数值差异，以及短运行保存后析构abort。

### 我怎么分析

- OOM先区分长序列反向峰值与生成侧资源竞争，避免只按短回答成功就启动长训练。
- 生成与训练使用不同数值路径，不能假定相同checkpoint就有完全相同log-prob。
- 保存成功后的析构故障与训练过程中出现NaN是不同问题，要分别检查checkpoint、退出和数值记录。

### 我做过哪些处理与效果

| 问题 | 已有处理 | 实际效果 |
|---|---|---|
| B/C长序列OOM | microbatch4改2，累积改2，保持有效回答batch4 | 两组10步训练与评测完成 |
| NF4/BF16同步 | 临时解量化权重加LoRA delta，加载到生成副本；检查冻结权重、重置cache | C64同步与参数更新检查通过，不原地merge训练权重 |
| 后端log-prob差异 | 记录差异，启用重要性修正 | C64平均importance ratio接近1，不能证明逐token完全等价 |
| 保存后析构abort | 成功路径保存、同步、清理资源后绕过析构 | 控制器成功退出；只是环境绕行，不是根治上游故障 |
| 生成慢 | vLLM固定工作量benchmark | 177.66→508.14 tokens/s，约2.86×生成吞吐 |

### 哪些还没有解决

生成2.86×不等于端到端训练2.86×；评分、反向、同步和sleep/wake仍有成本。需要分阶段计时才能量化完整训练效率，不能用框架接入成功代替能力收益。

**面试表述：**“工程上我先做长序列预检，用梯度累积降低单次反向显存；接入vLLM后检查权重同步和采样偏差。吞吐收益只报告实际测量的生成阶段，没有扩展成端到端加速。”

证据：[B/C运行状态](../closure_BC_results/status.json)、[C64报告](../vllm_C64_results/REPORT.md)、[vLLM迁移与benchmark](../vllm_speed_tools/README.md)。

## 八、我最终解决到什么程度

| 问题 | 当前结论 |
|---|---|
| SFT格式收益与能力损失并存 | 现象已确认；GRPO恢复部分能力，但SFT退化根因未充分分离 |
| 重复推导与收尾 | 有短诊断改善例子，不能宣布普遍解决 |
| 奖励项不提供独立信号 | 已定位本轮实验可识别性问题，新的有效训练收益待验证 |
| 评分器漏判 | 修复已识别部分判定并复算优势，未验证重训收益 |
| LR平台期假设 | 已有对照，未见一致收益，没有证明主因 |
| 无相对奖励差异题组 | 已做静态筛选与在线审计，动态采样待做 |
| OOM与单卡生成 | 已有可运行处理和生成吞吐收益，端到端效率待测 |

项目主线可以这样讲：

> 我先发现SFT格式变好但数学正确率下降，因此把loss与生成能力分开检查，并核对监督边界和数据问题。GRPO恢复了部分正确率和收尾，但训练过程中还有奖励不触发、奖励冗余、评分漏判及收益平台等问题。我分别通过rollout审计、评分修复和学习率对照检验这些解释；工程上用长序列预检、梯度累积和vLLM适配使流程能运行。最终保留改善和失败两类结果，没有把每个假设都说成已经解决。
