# 下一轮实验：假设与验收标准

以下均为计划，未在本次启动训练或产生新指标。已有测试集已用于反馈，后续若反复调参，应另建未使用的确认集，不再把旧测试叫全新盲测。

## H1：SFT 数据质量和更新幅度影响能力保留

做 2×2 对照：原始数据/复核数据 × lr=5e-6/2e-5。尽量保持训练样本数、难度、题目来源、格式和更新次数匹配，避免把新旧数据数量差异误认为清洗效果。每个条件先 1 个 seed 筛查，再对主要候选用 3 个 seed 验证；任何成本估算都需用短运行实测，不把计划写成已跑完。

固定 Base、LoRA、模板、completion-only loss、EOS、max_length 和评测解码。保存训练数据哈希、adapter 哈希、配置、loss、gradient norm、实际步数及被截断样本数。主要指标为确认集自动判对率，辅助指标为格式且 EOS、截断、平均/中位 tokens、未确认评分比例。

验收：相对 Base 的判对率在预先约定容忍范围内，同时改善格式与截断。允许容忍多少百分点应在看结果前确定。若失败，报告完整矩阵，不选一个次要指标宣布成功。

## H2：格式奖励有独立增益，还是被正确性奖励掩盖

从同一 SFT checkpoint 开始，对照 correctness-only 与 correctness+format(0.1)，保持题池、预算与随机种子一致。记录每组奖励方差、0/4–4/4 组成、非零 advantage 比例、KL、clip fraction 和有效 token。

格式奖励是否有效要看组内是否产生差异，以及最终格式是否改善。不能只报告奖励均值升高；也不能把组标准化下奖励绝对值增大等同于更强学习信号。

## H3：截断组全屏蔽的代价是否值得

历史策略只要任一回答无 EOS 就屏蔽整题组（含 KL）。比较此策略与明确设计的替代策略之前，先确认 TRL 版本的 mask/advantage 语义与 off-policy 处理，加入小规模可手算案例和真实长回答 preflight。记录被丢弃题组的难度分布，不能直接换 mask 后把统计改善当能力提升。

## H4：生成吞吐能否转化为实际训练吞吐

在相同 checkpoint、同一输入和固定 token 工作量下测量 generation、同步、reference scoring、policy scoring、backward、optimizer、sleep/wake。分别报告生成 tokens/s、每步 wall time、峰值显存和总有效 tokens/s。短运行 3 次，排除加载与 warmup，报告波动。历史 2.86× 仅作生成 benchmark 对照。

## 交付规范

每项实验产生独立配置、原始日志、checkpoint hash、数据 hash 和逐题结果。原始与事后修复字段分离；存在评分未确认时单列。报告成功、退化与无结论三类结果，不编造学习曲线、日志、消融数值或“先发现问题”的时间线。
