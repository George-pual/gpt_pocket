## 2. E01：早期B/C奖励对照与OOM处理

**目的：**对比正确性＋软长度惩罚，与额外加入结束奖励的方案。

**记录：**状态文件的UTC时间转换为北京时间，运行开始于2026-10-09 16:13:34，结束于17:02:12。时段包含预检、两组训练和评测，不是单组训练耗时。

| 配置 | B | C |
|---|---|---|
| 初始化 | 同一个补充SFT adapter | 同左 |
| 训练量 | 10步 | 10步 |
| 学习率 | 5e-6 | 5e-6 |
| 每题回答数 | 4 | 4 |
| 奖励 | 正确性＋软长度惩罚 | B＋正确且格式完整、有EOS时加0.1 |
| 长度惩罚 | 3382 tokens后线性增加，3894处为−0.5 | 同左 |
| loss / scaling | grpo / group | 同左 |

### 遇到的问题与处理

**记录：**microbatch=4的长序列反向传播预检发生OOM。runner记录了`preflight_m4`失败，随后`preflight_m2`通过，最终B/C统一使用microbatch=2、梯度累积=2，有效回答批量保持4。

**实际效果：**完成两组训练及评测。这个处理证明该配置能运行，不证明它吞吐最优，也不证明训练正确率提高。没有证据把其他阶段的batch配置混入本次OOM记录。

### 结果与后续诊断

| 固定8题诊断指标 | B | C |
|---|---:|---:|
| 最终答案正确 | 3/8 | 3/8 |
| 正常结束 | 8/8 | 8/8 |
| 截断 | 0/8 | 0/8 |
| 平均tokens | 804.875 | 783.25 |
| 训练耗时 | 约19.7分钟 | 约21.9分钟 |

**记录：**两组训练回答均未达到长度惩罚阈值，惩罚一直为0；C组14条正确回答全部格式完整、有EOS，实际总奖励等于1.1×正确性。不能把训练在线正确数9/40与14/40当作独立测试的能力提升。

**分析：**在组内标准化下，统一正比例缩放基本被抵消，结束奖励没有提供可识别的独立方向；长度惩罚也没有被这批样本真正检验。C的回答均值略短，不能归因于惩罚，更不能据8题证明泛化提高。

**待验证：**先统计真实采样分布中的奖励触发率与advantage变化，再设计可以区分奖励作用的对照，不直接增大奖励系数重跑。

**证据：**[状态文件](../closure_BC_results/status.json)、[结果报告](../closure_BC_results/REPORT.md)。

## 3. E02：C64 vLLM迁移与训练链路诊断

**目的：**在单卡上运行vLLM生成与NF4策略训练，验证权重同步、参数更新与奖励实现。

**记录：**从E01的C adapter继续，训练池64题；microbatch=2、梯度累积=4、每题4答、generation batch=16、lr=5e-6、beta=0.04。checkpoint25恢复后沿用原100步调度，在累计64步停止。

### 遇到的问题与处理

1. **NF4训练与BF16生成不是同一数值路径。** 解量化NF4与LoRA delta只加载到vLLM副本，不原地merge训练权重；检查冻结参数指针/版本，重置prefix cache，并开启重要性修正。
2. **短运行曾在保存后解释器析构时abort。** 成功路径保存并同步文件、关闭引擎及分布式资源后，以`os._exit(0)`绕过析构。该处理是针对特定环境的退出绕行，不能说已根治上游析构故障。
3. **显存峰值统计异常。** vLLM睡眠分配器影响PyTorch峰值计数，出现大于平台物理显存上限的统计，不把它当作真实物理占用。

### 实际结果

- 最终adapter与checkpoint-64哈希一致，参数更新及冻结权重检查通过。
- loss、梯度、KL均为有限值；平均token log-prob差约0.00456，平均importance ratio约0.99984，不等于逐token完全等价。
- 完成记录的runtime约2320.7秒；这是该完成记录的计时范围，不当作包含此前全部重启的端到端耗时。
- 记录528条生成回答、132组；64步对应512个训练回答位置。恢复后重采样导致生成记录更多，不能把528条全部叫作反向传播样本。
- 63/132组总奖励相同，约47.73%，缺少组内相对策略信号。
- 固定8题同卡对照，初始C为3/8，64步后为1/8。样本太小，不认定统计显著退化，但不支持采用后者作为能力改进。

**分析：**训练链路可用，不等于数学能力提高。优先检查有效题组和奖励冗余，不能只看loss接近零或追加更新步数。

**证据：**[C64报告](../vllm_C64_results/REPORT.md)、[完成记录](../vllm_C64_results/completion_summary.json)、[迁移配置](../vllm_C64_results/migration.json)。

## 6. E04：GRPO主实验0–1024步

**目的：**从SFT v3出发，利用最终答案正确性和格式奖励优化回答。

**数据准备记录：**GSM8K与MATH L2–3候选去重后10412题，每题4条筛选回答；筛出混合组，再排除已知重叠及截断等情况。第一阶段准备池3816题，但实际仅消耗2048个不同题组。

| 项目 | 实际配置 |
|---|---|
| 初始化／reference | SFT v3 / 冻结原SFT v3 |
| 更新 | 1024次 |
| 学习率 | 5e-6线性降到0，warmup2步 |
| 每题生成数 | 4 |
| generation batch | 32回答＝8题 |
| optimizer有效回答batch | 2×累积4＝8回答＝2题 |
| 回答预算 | 3894 tokens |
| KL beta | 0.04 |
| loss / scaling | grpo / group |
| seed / data_seed | 3407 / 3407 |

**奖励：**历史v1正确性0/1，加格式分量0.05＋0.03＋0.02，总上限1.1。没有长度或重复惩罚，也没有逐步推理正确性奖励。

**记录：**一个生成批次供连续4次optimizer更新使用，`num_iterations=1`不等于每次更新都重新生成。实际`batched_forward=False`、`score_batch=1`，不能写成已实现真正批量前向加速。

**实际完成：**2048个不同题组、8192条回答；训练耗时14343.7秒，约3.98小时，不含筛选与评测。保存累计256、512、1024 checkpoint。

## 7. E05：GRPO主实验1024→1536步

**记录：**合格池扩大至7527题，从第一阶段未使用题中选择1024题；加载GRPO-1024 adapter，重建optimizer/scheduler，reference仍固定原SFT v3。

- 额外512次更新，峰值lr=2e-6，warmup2步，线性降到0。
- 新增1024个不同题组、4096条回答。
- 本阶段耗时7602.5秒，约2.11小时，不含筛选与评测。
- 本地checkpoint-256对应累计1280；checkpoint-512对应累计1536。
- 两阶段累计3072个不同题组、12288条回答；53组因任一回答无EOS被整组屏蔽，剩3019组。

**边界：**是从adapter续训，不是完整optimizer-state无缝恢复。完整Base/GRPO权重未包含在本地交付包中，不能称所有资产已可端到端离线复现。

**E04/E05证据：**[训练交付报告](../deliverables/SFTv3_GRPO_1536_training_handoff/TRAINING_REPORT.md)。

## 8. E06：学习率A/B对照

**待检验假设：**后期LR逼近零可能限制更新，恒定学习率是否改善结果？

**已执行配置：**两组从同一GRPO-1024 checkpoint开始，使用相同题池、题序和修复后的v2奖励，各额外256步。A为2e-6线性衰减并保留2步warmup；B全程恒定2e-6、无warmup。optimizer均重建。

| 历史评测口径 | A线性 | B恒定 | B−A |
|---|---:|---:|---:|
| GSM8K /1319 | 1119 | 1110 | −9题 |
| MATH /200 | 138 | 141 | ＋3题 |

**实际效果：**没有两个测试集一致的收益，配对不确定性未排除波动，不把恒定2e-6设为已验证更优默认值。

**异常记录：**A第134步记录KL=412.97、grad_norm=1994.64，随后恢复；有限值不代表全程平稳。不能凭这一个尖峰解释全部测试差异，也不能把它归因于B恒定LR。

**实验局限：**warmup也不同，因此比较的是两套调度策略，尚未严格分离衰减本身；仅一个训练seed，历史评分口径不能直接混入v3.2总表。

**证据：**[配置说明](../lr_ab256_experiment/README.md)、[完整对照分析](../lr_ab256_experiment/ANALYSIS.md)。

## 9. 训练奖励与评测评分的事后审计

**记录：**主训练实际使用历史v1奖励。后续v2离线复核在6032条MATH训练回答中识别12条正确性0→1，涉及11个有效题组，改变44条回答的advantage。

**具体问题：**最终答案包含自然语言等表达时，旧规则可能漏判；同组基线随之改变。一个实例中，第三条回答的中心化奖励由−0.5变为＋0.25。

**实际处理效果：**修正已识别判定、重建受影响相对信号，保留原始奖励及历史文件。没有重训或修改已有模型，因此不是模型正确率提升；12条也不是全部潜在漏判上限。

**证据：**[奖励信号审计](../datasets/grpo_candidates_gsm8k_math_l2_l3/training_audit_1536/reward_signal_audit_v2/ANALYSIS.md)。

## 12. 面试可用的复盘表述

> 我在开源框架上完成了单卡SFT与GRPO实验。早期长序列预检发生OOM，我降低microbatch、用梯度累积保持有效批量，使B/C对照完成。后续分析发现新增长度奖励根本没触发，结束奖励又近似被组内标准化抵消，因此没有把实验没涨点简单归因于训练步数。vLLM迁移中检查了冻结权重、参数同步与数值差异，也记录了保存后的析构异常。主实验GRPO恢复了SFT的一部分能力损失，但没有全面超越Base；学习率对照也未得到一致收益，所以继续用数据与更新幅度消融定位问题。
