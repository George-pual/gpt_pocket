# 当前 GRPO 数据方案：先分题，再按起点模型筛选

状态：下一轮实验计划，尚未按本方案构建题池或启动训练。更新日期：2026-10-13。数据范围与预算统一见[MATH L2–3主线配置](MATH_L2_L3_DATA_CONFIGURATION.md)。

本文统一当前 MATH L2–3 目标下的 GRPO 数据安排；其他文档中的 GRPO 通用规模与生成预算以本文为准。历史 SFT v3 → GRPO 记录保持原样，不能把本方案写成已完成经历。

## 1. 先明确 SFT 与 GRPO 分别需要什么

- SFT：题目 + 值得模仿的完整正确解答；用解答作为监督目标。
- GRPO：题目 + 可靠的参考答案 gold；策略在线生成解答，奖励函数根据 gold 判分。gold、官方解答和离线筛选回答都不能进入模型看到的题目 prompt。
- GRPO 初版优先当前模型有时答对、有时答错的题。离线发现过正确回答不等于该题已经稳定掌握，也不认证正确回答的全部推导。

这次先确定一个合格 SFT checkpoint，再用它筛题并作为 RL 起点。如果最后采用 Base 直接 GRPO，就重新用 Base 校准；不能沿用其他 checkpoint 的难度标签。比较多个 GRPO 参数时固定同一份题池、同一起点和评分版本。

## 2. 数据从哪里来，如何与 SFT 分开

主实验只使用 MATH train Level 2–3。GSM8K train仅在开发验证显示相应短板时作为独立补充对照，不默认混入。最初505条SFT来源为用户确认的unsloth/OpenMathReasoning-mini，不是MATH等级子集。

顺序为：

1. 记录来源版本、原题 ID、题面、gold；检查缺图、条件缺失、参考答案异常。
2. 排除评测题的原题、已发现的翻译/改写；同题多轨迹归为一个题簇。
3. 先锁定开发验证与确认数据，再把剩余题簇分为 SFT 和 GRPO。新实验开发验证建议200道MATH题；额外确认数据另行锁定并计入排除清单。不能将已用于训练或选方案的数据重新称为盲测。
4. 新SFT实验预留600道MATH候选，最终合格示范数由筛选结果决定；GRPO从其余独立题簇中选择。
5. SFT候选即使4次生成全错，也保留在SFT所属分区中作失败分析或教师解答补充，初版不自动转给GRPO，避免根据采样结果来回移动分区。

本地 MATH L2–3 有2940条原始记录，历史规范化去重后2939题。若预留200道MATH开发题、占用600道MATH SFT题，则最多还剩2139题；这**还没有扣除外部505题重叠、额外确认数据、近似重叠、缺图和判分不支持等损耗**。所以不能预先承诺筛出几千道独立MATH合格题。新训练起点若继承旧adapter，还需计入其历史训练暴露。

MATH保留七个学科及原始Level；GSM8K没有MATH Level，不补造等级。题簇/近似重叠审查需要另外完成，现有精确去重工具不能证明不存在语义重叠。

## 3. 先验证评分是否可靠

本项目已有Math-Verify判分链路：`screen_grpo_candidates_v3.py`调用`verify_final_answer`，由`math_verification.py`提取最终答案、解析表达式并调用Math-Verify的`verify`。本节是在抽查这条现有链路的提取、解析及异常处理，不是另写一套数学判分器，也不是逐题请大模型打分。实际判分入口可能包含数值快速路径，具体以冻结代码版本为准。

每题需要可靠gold，但不必为GRPO额外生成一份长标准解答。官方解答只在审查gold、歧义与争议样本时使用。

对当前MATH/GSM8K题目，直接沿用Math-Verify判最终答案，重点抽查答案是否提取正确、等价表达能否识别、是否发生解析异常或超时。只有实际发现题目信息缺失或现有代码无法可靠判分时，才暂缓该题；不能因为答案是集合或多个根就一律排除。

2026-10-12检查本地MATH train的7500条题面（其中L2–3原始行2940条），检索prove、proof、show that、demonstrate that后人工查看命中项，未发现要求提交证明的题；两个命中分别是单词PROOF的排列计数和生态数量应用题，并非证明题。这是关键词检查及命中复核，不冒充全量逐题语义审查。此前“过滤证明题”属于过于泛化的建议，已从当前执行要求中删除。

对回答区分：判对、明确判错、未确认。解析异常、超时和不支持的等价表达不能自动算数学错误。明显未给答案可按预先规定的规则判失败，并单记原因。不能在全文中搜索gold，只能独立提取最终答案后比较。

先抽查评分的正例、负例、未确认和不同答案类型，保留争议原文。gold与自身比较通过只表示解析器能处理它，不表示gold数学上正确。筛选与在线奖励应使用同一冻结正确性判定逻辑；更换版本后重算全部保留筛选回答，再冻结分桶。离线审计评分器不能未经适配直接视为已经接入在线奖励。

## 4. 用最终选定的 SFT 模型做初筛

初筛只做推理，不更新参数。先选最多512道MATH GRPO候选做试运行；按学科和Level覆盖抽样，固定顺序与seed。这些题本来属于训练分区，可以纳入后续筛选，不能又作为开发验证集。

| 项目 | 当前统一设置 |
|---|---|
| 校准模型 | 最终选定SFT checkpoint，保存权重/配置哈希 |
| 每题采样 | 4条，G=4 |
| 随机生成 | temperature=1.0，top_p=1.0，top_k关闭；固定并记录min_p、重复惩罚、stop和seed规则 |
| 题目模板 | 与后续GRPO一致，gold不出现在prompt |
| prompt预算 | 1024 tokens；过长题先处理，不能静默截题 |
| completion预算 | 3894 tokens，与当前GRPO基线一致 |
| 上下文容量 | 必须容纳实际prompt + completion；沿历史8192容量检查硬件可行性 |
| 评分 | 冻结版本，保存每条回答的正确性、格式、EOS和截断状态 |

SFT的2048是监督训练总序列预算，不能拿来替代这里的GRPO completion预算。若硬件要求更短预算，需要先确定新预算，再统一校准和训练；不同预算结果不能混为同一个难度桶。512题初筛产生2048条回答，不是2048道题。

记录 k=判对数、u=未确认数、t=截断/非正常结束数。先判断评分和预算是否正常，再按k分桶。初版主池只接受u=0、4条均正常结束、题面/gold已过检查的题；格式标签不合规不自动否定数学正确性，格式另记。结束异常题进入诊断队列，不从4条中删掉异常回答后重算比例。

排除结束异常会偏向更短、更易完成的题，应报告被排除学科及比例。如果大量题受预算影响，先修复预算或停止行为问题再整体校准，不能靠排除大量长题宣称数学难度筛选成功。

## 5. 难度怎么分，怎么组成训练池

| 4次采样判对数 | 含义 | 初版处理 |
|---|---|---|
| 0 | 这次没找到成功回答 | 检查gold、评分、题目条件和预算；保留难题诊断队列 |
| 1 | 较难但已有成功回答 | 挑战桶 |
| 2 | 成败都出现 | 中间桶 |
| 3 | 大多成功但仍有失败 | 巩固桶 |
| 4 | 这次全部成功 | 保留容易题诊断队列 |

这只是当前模型、当前解码预算下的粗分级，k/4不是精确成功率，也不是pass@4。0/4、4/4都可能只是有限采样结果；它们是暂不优先进入主池，不是永久无价值。

首轮合格池以**最多1024道不同MATH题**为预算上限。合格题不超过上限时全部保留；超过时按学科、Level和k分层抽样，接近合格池实际分布。先不强制k=3/2/1为25%/50%/25%，避免为未经验证的比例丢弃稀缺题目。

可执行的抽样顺序：先统计合格池的subject、Level和k，再按实际分布确定配额，桶内固定seed随机选题；稀疏交叉格优先检查学科覆盖，不强求所有交叉格都有题。若关键学科消失，回查筛选原因，不为凑比例加入问题样本。

**不足时的优先级：题目和判分可靠 > 避免学科严重缺失 > 题池规模。**合格MATH不足时缩小总池，不用GSM8K硬填到1024。不复制同题凑不同题数，也不无限增加采样直到偶然答对。

1024是本项目首轮预算，不是上游最优配方。2/4并不保证训练时最好；默认保持实际合格池分布，不先加“先易后难”的课程变化。GSM8K补充与难度重采样都属于后续单独对照。

0/4和4/4中按来源/学科固定抽取小批用于诊断，若追加采样则保存所有轮次，原始k/4标签不覆盖。第一版重测用于决定是否值得开展新一轮校准，不择优取一轮混合结果直接补进主池。

## 6. 候选、合格池与实际训练用量分开

| 阶段 | 计划规模 | 解释 |
|---|---|---|
| 初筛试运行 | 512候选题 × 4答 | 校验评分、分桶产出、长度与生成成本 |
| 分批扩筛 | 按剩余来源题数和预算决定 | 用试运行的分来源合格率估算，不预设一定有6000题可用 |
| 冻结合格池 | 最多1024不同题 | 不代表已全部训练；其余合格题可留作扩展储备 |
| 首轮GRPO对照 | 每臂最多256 updates | 沿现有每次更新通常2题×4答，计划约512问题位置、2048条在线回答 |
| 后续扩展 | 通过验证再使用剩余题 | 不在试运行前承诺累计训练1500–3000题 |

对照实验两臂使用相同题序。无放回的一轮可控制重复；但实际消费受生成缓存、mask与trainer行为影响，必须从rollout记录统计。分别报告生成题组、被mask题组、参与损失的组、非零总奖励advantage组和不同问题数，不能按updates反推成已完成事实。

离线筛选的4条回答只用于选题与审计，**不直接作为这轮GRPO的训练轨迹**。正式训练由当前更新中的策略重新生成，因此筛选时1–3/4，训练时仍可能0/4或4/4。

## 7. 训练后根据什么调整数据

第一轮固定题池与采样方式，正确性奖励0/1、辅助格式奖励沿项目基线；不同时换数据比例、奖励、学习率和在线过滤策略。

| 观察到的现象 | 先查什么 | 有依据后再做的对照 |
|---|---|---|
| 大量0/4 | 是数学错误，还是gold漏判、解析、截断；按来源分开统计 | 修评分则全量重算；确为难度不合适再调整候选 |
| 大量4/4 | 是否只集中在容易来源，是否仍有格式差异 | 用当前策略重校准尚未训练的候选，比较替换题池 |
| 总奖励零方差组增加 | 各奖励分量、EOS mask、实际有效组数与生成成本 | 再比较有重试上限的在线补采样 |
| reward上升但开发集不涨 | 是否只是格式涨、漏判减少或抽到更简单题 | 固定开发集、拆分正确性/格式并抽查回答 |
| MATH停滞、GSM8K改善 | MATH实际采样占比、学科覆盖、错误类型 | 固定其他因素比较来源配比，而非马上加大学习率 |

正确性全同不等于总奖励全同：格式可能不同。总奖励全同时组内策略advantage为零，但保留KL项时仍可能有KL梯度。历史整组EOS屏蔽还会影响有效更新，所以分别统计，不能把0/4+4/4比例当作全部无效更新比例。

数据消融只优先做一项：相同可靠候选范围内，未经模型难度过滤的来源分层随机池 vs 1–3/4混合池。固定题量、来源目标、起点、训练预算与评分，匹配并报告学科/长度分布，另计筛选成本。该实验检验整个选题方案；若要单独验证25/50/25，另比较同一1–3/4母池的自然比例，不把两种作用混为一谈。

## 8. 落地文件与现有代码边界

建议产物：

- `split_manifest.json`：来源版本、题簇、各分区及排除清单哈希。
- `grpo_candidates.jsonl`：题面、gold、来源/学科/Level；gold作为评分元数据，与prompt分开。
- `screen_raw.jsonl`：四次生成原文、token数、结束状态、模型与配置版本。
- `screen_scores.jsonl`：逐条判分、未知/截断原因、k与分桶。
- `grpo_selected.jsonl`：最终选中题ID、桶、选择依据；不含可见于prompt的参考解答。
- `selection_report.json`：各来源/学科筛前筛后数量、实际比例、排除原因、生成成本。
- `train_consumption.jsonl`：正式训练生成、屏蔽和参与更新的题组记录。

这些是待构建文件，列出名称不表示已经生成。项目已有[历史G4筛选脚本](../vllm_speed_tools/screen_grpo_candidates_v3.py)，但它固定历史v3 adapter哈希，使用历史评分入口；新起点、未确认分流和新配额需要适配。另一个[历史筛选入口](../vllm_speed_tools/screen_sft_difficulty.py)默认16次采样、20%–70%门槛及min_p=0.1，不能当作本方案G4配置直接运行。本次只统一计划，没有修改训练或筛选脚本，也没有启动GPU任务。

## 9. 面试时如何解释

> 我先把训练题分给SFT、GRPO和开发验证，避免同题示范与评测混在一起。SFT选值得模仿的解答；GRPO保留题目和可靠gold，再用最终起点模型每题采样4次，优先选有成功也有失败的题。难度同时记录数据集等级和当前模型的采样表现，解析异常、截断另外处理。下一轮计划以MATH为主，混合1/4、2/4、3/4三类题；训练时重新生成回答，并通过实际奖励方差和验证效果检查这套筛选是否有用。

其中下一轮的题量、配比和筛选改造尚未执行；历史主线确实做过G4混合组筛选，不能把新计划数值放进历史结果。

参考：[Open-R1 pass-rate filtering](https://github.com/huggingface/open-r1/blob/main/scripts/pass_rate_filtering/README.md)支持生成后按正确比例筛选可验证任务；[DAPO §3.2](https://arxiv.org/html/2503.14476v2#S3.SS2)讨论动态采样。这些支持方法方向，不为本文具体题量、比例或收益背书。
